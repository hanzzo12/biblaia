### 2.1 სექცია 1 — ქვეყანა, ქალაქი, დაწესებულება

- ზემოთ ერთი საძიებო ველი „ძიება (ქართულად ან ლათინურად)“ — ARIA combobox + listbox; ეძებს ქვეყნის, ქალაქის და დაწესებულების ka/en სახელებსა და ალტერნატიულ დაწერილობებში (რეგისტრი, დიაკრიტიკა და დეფისი ნორმალიზდება). შედეგში ჩანს „დაწესებულება — ქალაქი, ქვეყანა“.
- ქვემოთ სამი კასკადური native `<select>` (ჭეშმარიტების წყარო): ქვეყანა → ქალაქი → დაწესებულება. ერთზე მეტი ქალაქისას ქალაქი ჯერ არჩეული უნდა იყოს; ერთი დადასტურებული ქალაქისას ავტომატურად აირჩევა და ხილულად იწერება („ქალაქი: ვენა — ავტომატურად არჩეული“). ბრიუსელში საელჩო, NATO და EU ცალკე ჩანაწერებია.
- დაწესებულების ინფო (ნორმატიულიდან): დაფინანსების ვალუტა, K, E, წყაროს მითითება. ნორმატიული მონაცემის არქონისას: „ამ დაწესებულებისთვის ნორმატიული მონაცემი არ არის — ოფიციალური თანხა დაუდგენელია“; ბაზრის ბლოკი მაინც მუშაობს.

**ბაზრის ბლოკი** (იმავე სექციაში, ქალაქის არჩევისთანავე; `aria-live="polite"`, `aria-busy` ჩატვირთვისას; მოლოდინი ფორმას არ ბლოკავს):

- ქირის ტიპი (radio): „ცენტრი — 1 საძინებელი“ (ნაგულისხმევი), „ცენტრი — 3 საძინებელი“ (მხოლოდ თუ პროვაიდერს აქვს), „ცენტრის გარეთ — 1 საძინებელი“ / „— 3 საძინებელი“. 2 საძინებელი არ არსებობს (ინტერპოლაცია არა).
- ქირა: „ცენტრში ბინის საშუალო საორიენტაციო ქირა“, თანხა + ვალუტა; „პროვაიდერის დიაპაზონი: low–high“ (არა „ნდობის ინტერვალი“); მოკლე განმარტება „ხარისხი, ფართობი, ავეჯი და უბანი განსხვავდება“; ქალაქი, როგორც პროვაიდერმა დაადგინა (`matchStatus`; ახლომდებარე ქალაქზე ცხადი გაფრთხილება); წყარო/attribution ბმულით; „მონაცემის განახლება: …“ (`sourceUpdatedAt` ან „უცნობია“) და ცალკე „მიღების დრო: …“ (`fetchedAt`).
- ინდექსები: „ცხოვრების ღირებულების ინდექსი (ქირის გარეშე)“ მთავარი; დამატებით „ქირის ინდექსი“, „ცხოვრების ღირებულების ინდექსი ქირით“; ბაზა „ნიუ-იორკი = 100“; შენიშვნა „ინდექსი ფულადი თანხა არ არის და არ ცვლის ბრძანების K-ს“.
- ქირასა და ინდექსს თავისი სტატუსის ნიშანი აქვს; ერთის არქონა მეორეს არ მალავს.
- ღილაკი „გამოვიყენო დაგეგმილ ქირად“ — აქტიურია მხოლოდ თუ `rent.average ≠ null` და ვალუტა = დაფინანსების ვალუტა (სხვა შემთხვევაში disabled + მიზეზი). G-ში წერს თანხას, წყაროს = „market“ და მეტამონაცემების ასლს. თუ G-ში უკვე მომხმარებლის თანხაა — inline დადასტურება „ჩავანაცვლო 1 500,00 EUR?“; ქალაქის შეცვლა/API-ის განახლება G-ს არასოდეს ცვლის. სხვა ქალაქიდან დარჩენილ G-ზე: „დაგეგმილი ქირა შეყვანილია სხვა ქალაქისთვის (ვენა). გადაამოწმეთ.“

### 2.2 სექცია 2 — რეჟიმი, თანამდებობა, სტატუსი, პერიოდი

- „გაანგარიშების რეჟიმი“ (radio, fieldset): „დანართი №2“ / „დანართი №3“ + №3-ის გამოყენების პირობის მოკლე ტექსტი და წესის ID (ბრძანება, პ. 37–39).
- „თანამდებობა“ — რეჟიმის მიხედვით `positionProfiles`-დან, პროცენტით: „მეორე მდივანი — 60%“. რეჟიმის შეცვლისას იგივე თანამდებობა ხელახლა ირჩევა თუ არსებობს, სხვაგვარად — ცხადი შეტყობინება.
- „სპეციალური სტატუსი“: „წარმომადგენლობის ხელმძღვანელი (ქირა და მაკლერი)“ — ტიპური ხელმძღვანელი თანამდებობისას წინასწარ მონიშნულია წარწერით „შემოთავაზებულია თანამდებობის მიხედვით“, შეცვლადია; „ხელმძღვანელის მოვალეობის შემსრულებელი (პ. 20¹)“; „ადმინისტრაციული მენეჯერი (პ. 20²)“. თითოეულს — სამართლებრივი საფუძველი და „საჭიროებს შესაბამის აქტს“ თუ ასეა.
- „თანამშრომლის ასაკი ან დაბადების თარიღი“ — არასავალდებულო; ცარიელი = უცნობი (დაზღვევა დაუდგენელი), ნაგულისხმევი არ აქვს.
- „საანგარიშო პერიოდი“: „სრული თვე“ (ნაგულისხმევი, თვე/წელი არასავალდებულო). `<details>` „დამატებითი: თარიღებით გაანგარიშება“ — დაწყება/დასრულება (`type=date`), ცვლილებების სია (თარიღი + რა იცვლება: ქირა / ოჯახის შემადგენლობა); შედეგში ჩანს თვეების მონაკვეთები „15/31 დღე“.

- ბარათის ბოლოს — ბირთვის პასუხიდან უფლებების მატრიცა: „7% დანამატი: კი / არა / დაუდგენელი“, „მოწყობა +10%“, „დაზღვევა“, „მგზავრობა“, „განათლება“ + მიზეზი და წესის ID. ასე ჩანს, რომ ერთი „ოჯახის წევრია“ ყველა უფლებას ავტომატურად არ იძლევა.

### 2.4 სექცია 4 — ქირა, განათლება, დამატებითი ხარჯები

- „ბინის ყოველთვიური ქირა (G)“ + „ქირის წყარო“ (radio): „ფაქტობრივი (ხელშეკრულებით)“, „დაგეგმილი“, „საბაზრო სცენარი“ (მხოლოდ ღილაკით). ცოცხალი მინიშნება: ცარიელი → „ქირა ჯერ უცნობია — შედეგი ნაწილობრივია“; `0` → „ქირა არ არის (G = 0)“.
- „განათლება“: თითო ბავშვზე (ოჯახის წევრის არჩევით, არა სახელით) კომპონენტები — „სწავლის საფასური“, „რეგისტრაცია“, „ნებადართული ტრანსპორტირება“, „კვება“; სასწავლო წლის პერიოდი; პირობები (სახელმწიფო ენაზე უფასო სასწავლებელი, არდადეგების ხელშეკრულება, ინდივიდუალური გადაწყვეტილება). ბავშვებს საერთო ზღვარი არ აქვთ.
- `<details>` „დამატებითი ხარჯები“ (დახურული ნაგულისხმევად, ბლოკები გამორთული სანამ მომხმარებელი არ ჩართავს): დაზღვევა (თითო პირზე პოლისის ფასი, უკვე გამოყენებული ლიმიტი); მაკლერი (ფაქტობრივი საკომისიო — ნაგულისხმევი არ აქვს, მომსახურების თარიღი, როტაციის დაწყება, უკვე მიღებული, დამადასტურებელი დოკუმენტი); ბარგი (ფაქტობრივი ხარჯი, უკვე გამოყენებული ლიმიტი); მგზავრობა (კატეგორია, მარშრუტი, ეკონომკლასის ფასი, შესადარებელი ბილეთი, პირადი ავტომანქანა); პირველადი მოწყობა (დღიური ნორმა ხელით + ვალუტა + წყარო + თარიღი; „დაუდასტურებელი“ ნიშანი); ავანსი (თანხა, დაფარვის თვეები); სხვა ხარჯი (კატეგორია, თანხა, დასაბუთება, „საჭიროებს მინისტრის გადაწყვეტილებას“).

### 2.5 სექცია 5 — შედეგი

`<section aria-labelledby>`; შეჯამების ზოლი `role="status"` (`aria-live="polite"`, მხოლოდ მოკლე ტექსტი, debounce ~500 ms). ზემოთ სისრულე: „სრული“ / „ნაწილობრივი — აკლია: ქირა, ასაკი (ოჯახის წევრი 2)“ / „დაუდგენელი“ (ბმულებით ველებზე). შემდეგ ბლოკები ამ რიგით:

1. **ყოველთვიური სამივლინებო თანხა (S)** — დიდი თანხა; `<details>` „როგორ დაითვალა“: H, A, K, C, D, E, T, G, F, ფორმულები, დაუფარავი ქირა `max(G − F, 0)`, `F − G` თუ დადებითია.
2. **ხარჯების ანაზღაურება (ყოველთვიური)** — განათლება თითო ბავშვზე: ხარჯი P, ზღვარი L, ანაზღაურება, საკუთარი წილი.
3. **ქირისა და შეყვანილი განათლების ხარჯის შემდეგ დარჩენილი თანხა** — `S + განათლების ანაზღაურება − G − განათლების ხარჯი`; ქვეწარწერა „სხვა ყოველდღიური ხარჯები (კვება, კომუნალური და სხვ.) გამოკლებული არ არის“. უარყოფითი ნაშთი ჩანს უარყოფითად.
4. **ერთჯერადი დახმარება** (მაგ. პირველადი მოწყობა) და ცალკე **ერთჯერადი ხარჯის ანაზღაურება** (მაკლერი, ბარგი, მგზავრობა).
5. **წლიური ზღვრები** — დაზღვევა თითო პირზე: ასაკობრივი ჯგუფი, ზღვარი, პოლისი, ანაზღაურება, საკუთარი ხარჯი; „ზღვარი მიღებულ თანხას არ ნიშნავს“.
6. **ავანსი და დასაბრუნებელი ვალდებულება** — თანხა, ყოველთვიური დაფარვა, დარჩენილი; არ ემატება არცერთ ჯამს.
7. **ბაზრის საინფორმაციო მაჩვენებლები** — წყაროთი და სტატუსით; „ოფიციალურ გაანგარიშებაზე გავლენა არ აქვს“.
8. **გაფრთხილებები, ვარაუდები, წესები და წყაროები** — თითო ნიშნავს ID-ს და წყაროს მითითებას (დანართი/პუნქტი/სტრიქონი); `rulesVersion`.

ყოველი სტრიქონი: სახელი, თანხა + ვალუტა (ან „დაუდგენელი“ + მიზეზი), სტატუსის ნიშანი („გამოთვლილი“, „სცენარი“, „დაუდასტურებელი“, „დაუდგენელი“, „არ ვრცელდება“). დაუდასტურებელი ნაწილი დასრულებულ ქვეჯამში არ ერევა. GEL ეკვივალენტი მხოლოდ ჩართვით, წარწერით „საპროგნოზო კურსი (ბრძანება, პ. 2), არა დაფინანსების დღის კურსი“. წლის პროგნოზი მხოლოდ მონიშნული სცენარით: „მარტივი სცენარი: უცვლელი თვე × 12“.

## 4 ხელმისაწვდომობა და ვალიდაცია

- ყველა ველს `<label for>`; ჯგუფებს `<fieldset>/<legend>`; checkbox/radio native ელემენტებია (არა `div onclick`); `<details>/<summary>` გასახსნელად.
- ხილული focus (`:focus-visible`, ≥ 3:1 კონტრასტი); ლოგიკური tab-რიგი; დამატების/წაშლის შემდეგ focus გადადის ახალ ბარათზე / წინა ელემენტზე; წაშლის ღილაკს `aria-label="ოჯახის წევრი 2-ის წაშლა"`.
- შეცდომა ველის ქვეშ: `aria-invalid="true"`, `aria-describedby` → ტექსტი; შედეგის ზემოთ შეცდომების ჯამი ბმულებით. `alert()` არ გამოიყენება.
- `aria-live`: შედეგის მოკლე ზოლი (`polite`), ბაზრის ბლოკი (`polite` + `aria-busy`), კრიტიკული შეცდომა (`role="alert"`).
- თანხის ველი: `type="text" inputmode="decimal"`. პარსერი (`format.js`): trim; ჯგუფის გამყოფი — space/NBSP; ათწილადი — ერთი `,` ან `.`; ორივე ერთად ან რამდენიმე → „გამოიყენეთ ერთი ათწილადი გამყოფი“; მაქს. 2 ათწილადი; უარყოფილია `-`, `Infinity`, `NaN`, `1e5`, `0x…`, ასოები; ზედა ზღვარი ველზე (ნაგულისხმევი 10 000 000) → „თანხა არარეალურად დიდია“. ცარიელი → `null` (უცნობი), არა 0. ბირთვს გადაეცემა ათწილადი **სტრიქონი** (`"1500.5"`), არა float. არასწორი ველი = უცნობი გაანგარიშებაში, სხვა მონაცემი არ იკარგება.
- ჩვენება: `1 234,56 EUR` (NBSP ჯგუფები, მძიმე) საკუთარი ფორმატერით, ICU-ზე დამოუკიდებლად; ყველა თანხის ელემენტს `data-value="1234.56"` (ზუსტი სტრიქონი) ტესტებისა და ბეჭდვის შედარებისთვის.

## 5 ექსპორტი, შენახვა, ბეჭდვა

- **JSON სცენარი**: `{ "schemaVersion": "scenario/1", "appVersion", "rulesVersion", "createdAt", "input": {…}, "marketManual": […] }`. პროვაიდერის მონაცემი ექსპორტში არ შედის, თუ ლიცენზია არ უშვებს (მხოლოდ ID/სტატუსი). ფაილი `rotation-scenario-YYYY-MM-DD.json`, Blob + `download`.
- **იმპორტი**: ზომის ზღვარი (≤ 256 KB), `JSON.parse` try/catch, სქემის ვალიდაცია (უცნობი/დაკარგული ველი, ტიპები, სტრიქონის სიგრძე, უცნობი ID, ვალუტა ∉ {EUR, USD, …}), რიცხვები იმავე პარსერით; `rulesVersion` განსხვავებისას — გაფრთხილება. შეცდომისას მიმდინარე ფორმა არ იცვლება; მიზეზი ჩამოთვლილია.
- **localStorage**: მხოლოდ ღილაკით „დამახსოვრება ამ მოწყობილობაზე“ (გასაღები `rotationCalc.scenario.v1`, იგივე სქემა); „გასუფთავება“ შლის შენახულს და ფორმას აბრუნებს საწყისზე (დადასტურებით). ავტომატური შენახვა არა; ყველა წვდომა try/catch-ში; პროვაიდერის მონაცემი არ ინახება.
- **ბეჭდვა** (`print.css`, `@page { size: A4; margin: 15mm }`): იმალება ნავიგაცია, ღილაკები, ძიება; ყველა `<details>` იბეჭდება გახსნილად (`beforeprint`-ზე `open`, `afterprint`-ზე აღდგენა); ერთი სვეტი; ბლოკებზე `break-inside: avoid`, სათაურებზე `break-after: avoid`; `overflow-wrap: anywhere` გრძელ ქართულ სახელებზე; ცხრილი `thead` გამეორებით. ზედა ნაწილი: სათაური, თარიღი, `rulesVersion`, პერიოდი; შემდეგ შეყვანილი მონაცემების ცხრილი (`print-only` სექცია), შედეგები, გაფრთხილებები, ვარაუდები, წყაროები, ბაზრის მონაცემი სტატუსით; ქვემოთ „საინფორმაციო გაანგარიშება; ოფიციალური თანხა დგინდება შესაბამისი აქტით“. ღილაკი იძახებს `window.print()`; README აღწერს „დანიშნულება: PDF-ად შენახვა“. ტექსტი რჩება ტექსტად (ჩაშენებული Noto Sans Georgian).

## 6 უსაფრთხო რენდერი

- `src/ui`-ში აკრძალულია `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, inline `on*` ატრიბუტები. ტესტი/grep ამას ამოწმებს build-ზე.
- `dom.js`: `h(tag, props, ...children)` — სტრიქონი ყოველთვის `document.createTextNode`; props-ის whitelist (`class`, `id`, `for`, `type`, `name`, `value`, `aria-*`, `data-*`, `role`, `href`…); `on*` უარყოფილია; `href` მხოლოდ `https:`/`http:` (პროვაიდერის `sourceUrl`), `rel="noopener noreferrer"`. `clear(el)` = `replaceChildren()`.
- `index.html` შაბლონი სტატიკურია; დინამიკური ყველაფერი `h()`-ით. CSP `<meta>`: `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; font-src data:; img-src data:; connect-src 'self'` (ოფლაინ ფაილში `connect-src 'none'`).

## 8 რა მჭირდება ბირთვის კონტრაქტში (`docs/contracts.md`)

1. `calculate(input, data)` — სუფთა, სინქრონული, არასრულ შეყვანაზე არ აგდებს; შეყვანის სქემა = სცენარის `input` (`schemaVersion`-ით) + `validateScenario(json)` იმპორტისთვის.
2. `result.completeness`: `complete | partial | undetermined` + `missingInputs[]` (`path` ველის ID-სთვის, ქართული ტექსტი).
3. თითო კომპონენტი: `{ id, category, label, value: string|null, currency, status: calculated|scenario|unconfirmed|undetermined|not_applicable, reason, ruleIds[], inputsUsed }`; `category` ∈ monthly / reimbursement / remainder / oneTimeAllowance / oneTimeReimbursement / annualCap / advance / liability.
4. ყოველთვიური დაშლა H, A, K, C, D, E, T, G, F, S + `uncoveredRent`, `rentSurplus`; ნაშთის ფორმულის წევრები ცალ-ცალკე.
5. თარიღების რეჟიმში `segments[]` (`from`, `to`, `days`, `daysInMonth`, კომპონენტები) და ჯამები.
6. თითო ოჯახის წევრზე უფლებები: `familyAllowance`, `settlementBonus`, `insurance`, `travel`, `education` → `{ eligible: true|false|null, reason, ruleIds }`.
7. განათლება თითო ბავშვზე (კომპონენტები, P, L, ანაზღაურება, საკუთარი წილი); დაზღვევა თითო პირზე (ჯგუფი, ზღვარი, პოლისი, გამოყენებული, ანაზღაურება, საკუთარი).
8. `warnings[]`, `errors[]` (`code`, `severity`, ქართული `message`, `ruleIds`, `path`); `assumptions[]` (მაგ. G = T ინტერპრეტაცია, დამრგვალების პოლიტიკა).
9. `rulesVersion` და `ruleId → { სათაური, წყარო: დოკუმენტი/პუნქტი/სტრიქონი/გვერდი }` ცნობარი.
10. ნორმატიული ცნობარის helpers: ქვეყნები/ქალაქები/დაწესებულებები (ka/en სახელები, ალიასები, ISO, `marketLocationId`), დაწესებულების ვალუტა/K/E ან „ნორმატიული მონაცემი არ არის“; `positionProfiles` რეჟიმზე (პროცენტი, შემოთავაზებული ხელმძღვანელის სტატუსი); როლებისა და სპეციალური სტატუსების enum ქართული სახელებით.
11. თანხები ათწილადი სტრიქონებით შესვლასა და გამოსვლაზე; GEL კონვერტაციისას `{ rate, date, purpose, source }`.
12. პროვაიდერისგან: `MarketData` (§11 ამოცანის) `rent.status`/`indices.status` ცალ-ცალკე, ზემოთ ჩამოთვლილი 9 მდგომარეობით; `parseManualMarketJson()` ვალიდაციით.
