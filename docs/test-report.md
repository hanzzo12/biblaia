### შემმოწმებლის e2e ტესტები (`tests/e2e/verifier.test.js`)

1. **ოფლაინ, `file://`:** ქსელი სრულად დაბლოკილია. ვენის ეტალონი იძლევა S 4985.16, ნაშთს 3423.16 და განათლებას 938.00. გარე მოთხოვნა 0-ია, კონსოლის შეცდომა 0.
2. **ბაზრის მდგომარეობები:** ტესტი უშვებს რეალურ ლოკალურ HTTP სერვერს (`dist/web`) და სინთეზურ `/api/market` v2-ს. შემოწმდა: fresh, cached, stale, partial (აკლია ელემენტები: ჩანს `—`, არა `0`), not_found, disabled, network_error, rate_limited (429), არასწორი JSON (→ invalid_response), timeout (ხელოვნური საათით, კლიენტის ლიმიტი 100 წმ). ყოველ მდგომარეობაში ჩანს ქართული ტექსტი, ხოლო კალკულატორი აგრძელებს მუშაობას: S = 4465.06, ხელით გამოთვლილი.
3. **ბაზრის განახლება:** H, K, E, D, T, F, S და ხელით შეყვანილი ქირა არ იცვლება. G ბაზრის ფასით მხოლოდ ღილაკითა და დადასტურებით იცვლება: 1800 → S 4615.06, ხელით გამოთვლილი. გაუქმებისას ქირა უცვლელი რჩება.
4. **კონფიდენციალურობა:** `/api/market`-ის მოთხოვნა არის მხოლოდ GET, მხოლოდ `location` და `currency` პარამეტრებით, ტანის გარეშე. ქირა, ასაკი და ოჯახი არ იგზავნება.
5. **შედარება:** დაემატა 5 დაწესებულება, მე-6 უარყოფილია. EUR და USD არ იკრიბება. თითო სვეტის S უდრის `calculate()`-ის შედეგს იმავე (ექსპორტირებული) სცენარით; ვენა = 4465.06.
6. **XSS:** payload ჩაიდო ოჯახის წევრის label-ში, პ.20¹-ის აქტის ველსა და იმპორტირებულ JSON-ში. არ შესრულდა და ჩანს მხოლოდ ტექსტად. JSON იმპორტი უარყოფს არასწორ სქემას (`schemaVersion` 99), სხვა `kind`-ს, უცნობ მისიას და დაზიანებულ JSON-ს.
7. **ეკრანი და ბეჭდვა:** `data-value` მნიშვნელობები იდენტურია. PDF-ის ტექსტში (pypdfium2) არის 4985.16, 3423.16, 938.00 და ქართული ტექსტი.
8. **375px:** ინდოეთის/ESCAP-ის გრძელი სახელით და 7 ოჯახის წევრით ჰორიზონტალური გადახვევა არ არის და სახელი არ იჭრება.
9. **ოფლაინი და HTTP:** ერთსა და იმავე სცენარზე ფინანსური `data-value` და `data-exact` მნიშვნელობები იდენტურია.
